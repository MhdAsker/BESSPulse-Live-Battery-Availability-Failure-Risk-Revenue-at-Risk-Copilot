# Data provenance

| Value | Meaning |
|---|---|
| `REAL` | Directly acquired external observation, such as ENTSO-E data |
| `SIMULATED` | Synthetic BMS/EMS/PCS/rack telemetry generated by the twin |
| `DERIVED` | Deterministic calculation from identified inputs |
| `MODEL_PREDICTION` | Output from a fitted statistical/ML model |
| `COUNTERFACTUAL` | Hypothetical scenario, not an observation |

Battery telemetry remains `SIMULATED`. ENTSO-E observations are `REAL`; their raw XML and retrieval metadata are content-hashed. Aggregated wind and other transformations are `DERIVED`. Missing market values remain missing rather than being fabricated or replaced with zero.

Fault schedules are synthetic ground truth for evaluation. They may define the healthy cohort during offline experimental training and annotate held-out diagnostics, but they are prohibited from predictor matrices, production feature generation, and inference. Ground truth does not change the provenance of actual telemetry.

Expected-power and expected-temperature outputs are `MODEL_PREDICTION`, even though their training telemetry is simulated. Actual-minus-prediction residuals, persistence features, dataset hashes, and evaluation metrics are `DERIVED`; metrics are more specifically derived model evaluation. Joining or persisting predictions never relabels actual telemetry.

Saved model metadata records the exact ordered feature contract, feature-set and model versions, dataset hash, split date ranges, random seed, candidate and test metrics, and creation time. Prediction records separately retain prediction and residual provenance. Joblib artifacts are trusted local project outputs and must not be loaded from untrusted sources.

Charts and reports must identify simulated observations, model predictions, and derived residuals near the displayed data. Real market context must never make simulated battery telemetry appear real.

Future delivery targets are `DERIVED FROM SIMULATED TELEMETRY`: they use future requested/actual power, not injected fault truth. Delivery-risk probabilities are `MODEL_PREDICTION`. Native importance, reliability summaries, and SHAP values are `DERIVED MODEL EXPLANATION`. The Prompt 5 experiment made no live ENTSO-E request and reports real-market ablation as unavailable.

Engineering/robust/residual anomaly scores, persistence, events, evaluation metrics, and site aggregation are `DERIVED`. Isolation Forest scores are `MODEL_PREDICTION / ANOMALY MODEL OUTPUT`, not probabilities. Injected truth is `SIMULATED GROUND TRUTH / EVALUATION ONLY`. Prompt 5 probabilities are read only for post-hoc descriptive analysis; the poorly calibrated 24-hour probability retains an explicit warning.

Availability capability, request sufficiency, downtime, derating events, limiting factors, and historical summaries are `DERIVED ENGINEERING ANALYTIC` from `SIMULATED` telemetry. They are not `MODEL_PREDICTION` and are not real commercial availability measurements. Optional risk remains `MODEL_PREDICTION`; anomaly provenance remains detector-specific; fault truth remains evaluation-only. None changes deterministic capability.
## Price forecast lineage

The historical price target is `REAL` ENTSO-E data. Exact price lags are `DERIVED FROM REAL`, and
calendar/rolling fields are `DERIVED`. A system forecast would remain a `REAL` ENTSO-E forecast,
but is admissible only when its publication vintage is causal for the forecast origin. Point and
quantile prices are always `MODEL_PREDICTION`. Prompt 8 uses no battery telemetry and makes no
claim that a predicted value is observed market data.
## Commercial lineage

Historical ENTSO-E price is `REAL`; forecast price is `MODEL_PREDICTION`; battery telemetry is
`SIMULATED`; availability is `DERIVED`; optimized dispatch and both benchmark revenues are
`COUNTERFACTUAL`; RevenueAtRisk is `COUNTERFACTUAL`; attribution is `COUNTERFACTUAL / DERIVED`.
## Alert lineage

Alerts are `DERIVED DECISION-SUPPORT OUTPUT`. They retain lineage to `SIMULATED` telemetry,
`MODEL_PREDICTION` risk/anomaly outputs, `DERIVED` availability, and `COUNTERFACTUAL`
RevenueAtRisk. Injected fault truth is `EVALUATION ONLY` and excluded from generation.

## API lineage

API provenance objects preserve upstream classes. Telemetry is `SIMULATED`, ENTSO-E observations
are `REAL`, availability and market transformations are `DERIVED`, delivery/price forecasts are
`MODEL_PREDICTION`, commercial output is `COUNTERFACTUAL`, and alerts are `DECISION_SUPPORT`.
Each object includes source/version/time metadata. Operational response models contain no fields
for injected fault truth, future delivery targets, time-to-failure truth, or evaluation severity.

## Dashboard presentation

The dashboard preserves API provenance as text badges with color as a secondary cue. Local
historical artifacts are labeled `DEMO / LOCAL DATA MODE`; their original provenance is retained.
Evaluation-only failure markers appear only on the Delivery Risk historical panel with the explicit
`SIMULATED EVALUATION GROUND TRUTH` label. UI formatting and animation never alter values or infer a
new health score. Counterfactual commercial panels always carry the P&L disclaimer.
